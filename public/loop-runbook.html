03 · Instructor commands

Run each live loop from a clean worktree.

Keep the scenario branch frozen. Let participants or the coding agent work only on the disposable codex/run-* branch.

Ready

PostgreSQL performance loop

Terminal A prepares the branch, database, and product server.

git fetch origin
git worktree add .worktrees/postgres-loop \
  -b codex/run-postgres-$(date +%Y%m%d) \
  origin/codex/scenario-postgres-page-load

cd .worktrees/postgres-loop
pnpm install
cp .env.example .env.local
pnpm db:setup
pnpm build
pnpm start

Terminal B runs the frozen evaluator:

cd .worktrees/postgres-loop
pnpm db:verify
pnpm perf:search

Stop only after p95 is below 300 ms, failures stay below 1%, checks exceed 99%, and both index plans pass twice consecutively.

04 · LLM-as-judge

Use judgment only after deterministic gates pass.

A judge is useful for clarity, completeness, and helpfulness. It should never be the only sensor for policy, security, citations, schema, or correctness.

Pin the dataset, rubric, judge prompt, model family, and model settings before the run.

Put policy, security, citation, schema, and correctness in deterministic graders.

Use the judge only for qualities that genuinely require interpretation.

Blind the judge to iteration labels, previous scores, and the expected winner.

Require repeated runs and report the distribution, not only the best result.

Never let the active loop edit its evaluator, threshold, rubric, or frozen cases.

06 · Scenario gate

Publish a scenario only when all eight conditions hold.

A frozen scenario must remain credible, reproducible, measurable, safe, and easy to reset before an instructor uses it live.

  1. A non-technical observer can explain the customer or operator impact.
  2. The starting failure reproduces at least three times.
  3. The baseline report is committed or attached to the scenario branch.
  4. The evaluator measures real behavior and cannot pass through a workshop-only flag.
  5. The loop has an iteration limit, time limit, escalation condition, and rollback path.
  6. Correctness, security, accessibility, and privacy guardrails prevent metric hacking.
  7. The final state is visible in the product and in a machine-readable report.
  8. A fresh worktree resets the scenario without destructive cleanup.
